# PRD · 小红书「作业榜」

> 来源：[Backlog](xhs-homework-board-backlog.md)（MVP #1–9，已确认 2026-10-21）
> 阶段：**准备开发**（交互与状态已细化，可直接喂给 AI coding agent）
> 平台：移动端（iOS/Android 触摸 UI），原型为 390×844 可交互 HTML
> 性质：个人作品集/概念项目，非官方，数据全部 mock

---

## 1. 为什么做

**用户**：看美食教程笔记的人（本案以「酱香饼」为例）。
**场景**：博主做法步骤多、食材杂，用户想知道「别人实际做出来什么样 / 有没有更简单的做法」，只能在几百条评论里翻图。
**核心 Job**：一眼看到大家的作业，并按「做法流派」快速找到适合自己的版本。
**支撑**：作者本人观察到美食教程评论区作业密集，但评论流里图片被文字淹没、无法比较（来源：自己观察，未做调研）。
**核心假设（要验证的一件事）**：把评论区图片作业聚合并按流派分组后，用户比翻评论区更快找到想跟做的版本。
**成功信号（概念项目，定性）**：5 个朋友试用，≥4 人能在 30 秒内说出「我想跟做哪个版本，为什么」。

## 2. 范围

### MVP 本期（Backlog #1–9）
1. 评论区顶部「作业榜」入口（一排缩略图）
2. 作业榜一级页
3. AI 流派 tag 筛选
4. 作业卡片 AI summary
5. 「综合」下的评论者 + 评论区一句话亮点
6. 左右滑动切换作业，summary 联动
7. 多图角标 / GIF / 视频自动播放
8. Magic move 展开大图详情（含评论详情）
9. 「我也发一张」悬浮按钮（仅入口 + 占位面板）

### 不做
发布全流程、排序、「最简单做法」AI 推荐、点赞收藏（Later）；真实数据抓取、分享拉新（暂不考虑）。

## 5. 功能细则

### 5.1 入口卡（P0）
- 位置：评论区标题与第一条评论之间。
- 内容：标题「作业榜」+「126 份作业」+ 右箭头；下方一排 5 张方形缩略图（圆角 8），最后一张叠加「+121」。
- 点击整个卡片 → push 进 P1。缩略图取「综合」前 5 条。
- 状态：加载中（骨架灰块）；作业数 < 3 时**不展示入口**（避免空洞）；数据失败时静默隐藏。

### 5.2 作业榜一级页（P1）
- **顶栏**：返回按钮 + 标题「酱香饼 作业榜」。
- **Tag 栏**：横向可滚动 chip；默认选中「综合」；chip 文案带数量（如「改良版 4」）。点击切换：卡片列表重新过滤，滚回第一张，summary 与亮点同步更新。
  - Tag 集：综合、改良版、少食材、升级豪华版、广东版、北方馕版、fusion 混合版（由 AI 聚类生成，按作业数降序，「综合」恒在第一）。
- **一句话亮点**（tag 栏下）：当前 tag 的 AI 总结，一行，最多 2 行折行。
- **作业卡片流**：横向 scroll-snap，居中吸附，两侧露出相邻卡片（peek）；卡片 3:4，圆角 16。
  - 左下角：♥ 点赞数；右下角：多图显示「N张」，GIF 显示「GIF」，视频显示时长「0:15」。
  - GIF / 视频：进入可视区**自动静音循环播放**，离开暂停；不显示播放按钮。
  - 非当前卡片缩小到 92% 并降低亮度，当前卡片 100%。
- **卡片下方信息区**（随当前卡片联动，切换时淡入淡出 ≤200ms）：
  - 作者头像 + 昵称 + 流派 tag；
  - ✨ AI 解读：一句话——做了什么、和原版相比差在哪、为什么值得看；
  - 💬 评论区说：评论区对这条作业的共识（「综合」下尤其突出）。
- **悬浮按钮**：底部居中「＋ 我也发一张」，安全区上方 24px；点击 → 打开 S1。
- **状态**：加载（骨架卡）、空（某 tag 无作业：插画 + 「这个流派还没人交作业，来当第一个」+ 发布按钮）、成功。

### 5.3 作业详情（P2，magic move）
- 点击 P1 卡片 → 被点卡片的媒体区域用共享元素转场放大到 P2 顶部大图位（约 380–420ms，ease-out），其余内容淡入。
- P2 同样是**横向并列大图**（同一作业集合、同一 tag 过滤），可左右滑动；下方评论详情随当前大图联动。
- 多图作业：大图右上角「1/3」，点击图片切换下一张。
- 评论详情：作者、发布时间、评论正文、✨ AI 解读、回复列表（至多 3 条 + 「查看更多」）、♥ 数。
- 关闭：左上角 ✕ 或系统返回；**反向 magic move**，大图收回到 P1 对应卡片（若用户已滑到别的作业，则收回到那一张）。
- 底部固定评论输入条「说点什么…」（原型只做样式）。

### 5.4 发布占位（S1）
- 底部 sheet：标题「我也发一张」，说明「完整发布流程在后续版本」，3 个图片占位格 + 流派选择 chip + 「发布」按钮；点发布 → 关闭并 toast「已收到（原型占位）」。

## 6. AI 能力定义（需先过 eval）

| 能力 | 输入 | 输出 | 质量门槛（概念项目） |
|------|------|------|------|
| 流派聚类 | 评论中的图片 + 文字 | 每条作业 1–2 个 tag | 小样本 20 条人工标注，一致率 ≥ 80% |
| 作业 summary | 单条作业图片 + 评论文字 | ≤ 40 字：做了什么 + 差异点 | 无事实性编造（图里没有的食材不能写） |
| 评论区共识 | 该作业下回复 | ≤ 30 字 | 引用真实回复含义 |

- **不确定时的兜底**：置信度低 → 只归入「综合」、不显示 AI summary（显示评论原文首句）。
- **用户纠错路径（Later）**：作者可修改 tag。
- **隐私边界**：只处理公开评论；不展示用户未公开的图片；AI 内容标注「AI 生成」。
- **原型实现**：全部 mock，预置 AI 结果，不调用模型。

## 7. 状态与异常清单（UX completeness）

| 入口卡 | 加载 / <3 条 / 失败 | 骨架 / 隐藏 / 隐藏 |

| 触控目标 | — | 所有可点击 ≥ 44×44 |
| 返回 | — | 手势/按钮/Esc 均可 |

## 8. 技术假设

- 原型：单文件 HTML/CSS/JS，无依赖；移动端优先，桌面端居中 390×844 手机框。
- 图片：用内联 SVG 生成「酱香饼」插画占位（不使用任何真实用户图片）；GIF/视频用 CSS 动画模拟。
- Magic move：FLIP + 幽灵元素（ghost clone）WAAPI 动画，不依赖 View Transitions API。
- 数据模型（mock）：`Homework { id, user, tags[], type: image|gif|video, count, duration?, likes, summary, crowd, comment, time, replies[] }`。

## 9. 验收标准

1. P0 显示入口卡，点击进入 P1。
2. P1 点击任意 tag，卡片列表与亮点同步变化；每个 tag 至少 2 条作业。
3. 左右滑动卡片，下方 summary 在 200ms 内联动。
4. 多图/GIF/视频角标显示正确；GIF 与视频自动动起来。
5. 点击卡片触发 magic move，大图从原位置连续放大，无闪跳；关闭时反向收回。
6. P2 可左右滑动，下方评论随之变化。
7. 悬浮按钮始终可见，点击打开占位面板。
8. 手机宽度（375）下无横向页面滚动、文字无截断异常。
